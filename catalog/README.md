# 游戏目录

`games.json` 是审核过的远程游戏列表。小懒的设置页面在“发现更多游戏”里列出这里的游戏，点“安装”后照样要用户确认权限。用户粘贴的地址如果在目录里，也会标成“已审核”；不在目录里的游戏仍然可以装，但会提示“未审核”。

小懒按**地址**认游戏，不按 ID。审核的是提交时的那个版本：游戏的版本或者要的能力变了，用户那里会显示“当前版本未经审核”，要再提一次 PR 更新条目。

设置页面打开时读取目录，读不到时用上次缓存的内容；GitHub 连不上时会换成 jsDelivr 镜像。

## 提交游戏

1. 按[游戏开发指南](../docs/game-development.md)，参考 [`templates/riddle`](../templates/riddle) 写好游戏，部署到一个公网地址，比如自己的服务器；有域名的话建议配上 https。`SKILL.md` 里要写 `author`。
2. 运行合规检查：

   ```bash
   agentcade-game check https://你的游戏地址
   ```

   全部通过后，它会打印一条目录条目。
3. Fork 这个仓库，把这条条目加到 `games.json` 的 `games` 末尾，提一个 PR。PR 里写清楚：
   - 游戏怎么玩，适合多大的孩子；
   - 用户说的话会不会被保存，保存多久，用来做什么；
   - 出问题时怎么联系你。
4. CI 会检查条目的格式，再读取游戏名片，核对它和条目是不是一致。通过后等待人工审核。

## 条目字段

| 字段 | 说明 |
| --- | --- |
| `id` | 游戏 ID，和名片一致，不能和内置游戏或目录里别的游戏重复 |
| `name`、`summary` | 名称和简短介绍，和名片一致 |
| `url` | 游戏地址，必须是公网地址；用 http 时设置页面会标出“未加密” |
| `author`、`homepage` | 作者和主页 |
| `version`、`capabilities` | 审核通过的版本，和它要的机器人能力 |
| `reviewed_at` | 审核日期，合并时由审核人确认 |
| `status`、`note` | `listed` 是在架；`removed` 是已下架，`note` 写原因 |

## 审核标准

- `agentcade-game check` 全部通过，能完整玩一局。
- 内容适合在家里玩：没有暴力、色情、赌博，没有广告和引导消费。
- 不冒充小懒或者系统，不向用户索要密码、验证码、住址、电话这类信息。
- 要的能力和玩法相符，比如不画图的游戏不申请画图。
- 隐私说明清楚，服务能长期稳定运行。

## 审核流程

1. 确认 CI 通过。
2. 本地跑一遍 `agentcade-game check <地址>`，再用 `agentcade-game chat <地址>` 玩一局，看内容是否符合标准。
3. 把 `reviewed_at` 改成当天，合并。几分钟后用户在设置页面点“刷新”就能看到。

## 下架

发现游戏有问题时，把它的 `status` 改成 `removed`，在 `note` 里写原因，比如“服务已停止”或“内容不适合儿童”。目录里不再显示它；已经装了的用户会看到红字原因和卸载建议，确认页也不再允许安装。

## 自己搭目录

设置页面“主 Agent”一栏的“更多设置”里，可以把 `GAME_CATALOG_URL` 改成别的目录地址，文件格式和这里一样。公网上的目录要用 https。
