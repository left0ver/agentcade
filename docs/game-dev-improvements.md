# 游戏开发体验改进清单

2026-10-22 从接入游戏的开发者角度通读[游戏开发指南](game-development.md)后整理。这份清单只依据指南的内容，没有对照代码，有些点代码里可能已经做了一部分，动手前先确认。2026-10-23 更新了进度。

进度：25 项里完成 8 项，部分完成 1 项。

## 优先级

| 级别 | 含义 |
| --- | --- |
| P0 | 已经踩过的坑、会挡住所有用户，或者成本很低、收益明显，先做 |
| P1 | 明显降低写游戏和调试的成本 |
| P2 | 扩展游戏能做的事，需要先设计 |
| P3 | 策略类，等第三方游戏多起来再定 |

成本：小是一两天以内，中是三到五天，大要一周以上，并且涉及协议。

## P0

- [x] **1. 开局和结束的钩子**（中）
  - 问题：开局要念的题面、结束时要公布的答案只能写进提示词，等大模型照做。真机测试时，海龟汤开局漏念了汤面，猜谜语放弃时没有公布谜底。另外，`end` 会自动结束这一局，但每个游戏还要写 `end_game` 工具，并在提示词里写“event 为 end 时调用”，两套机制容易混。
  - 做法：`SkillAgent` 增加 `on_start()` 和 `on_end()`：返回必须说的内容（题面、没揭晓的答案、得分），由框架保证说出来，大模型只负责前后的串场。`end_game` 工具不再需要。
- [x] **2. 消息发到用户填的地址**（小）
  - 问题：`PUBLIC_URL` 必须和用户填的地址完全一致，填错了要到开局才报错，部署猜谜语时遇到过 HTTP 308。名片里的消息地址也可以和用户填的不一样，用户说的话可能发到没同意过的地方。
  - 做法：客户端只把消息发到用户填的地址，名片里的消息地址只用来核对；`PUBLIC_URL` 只在需要时才填。
- [ ] **3. 缺配置的内置游戏不挡启动**（中）
  - 问题：新加的内置游戏有必填密钥时，所有用户升级后应用都会停在设置页面；每个内置游戏还要单独填一份大模型密钥。
  - 做法：配置不全的游戏标成“需要设置”，暂时不能玩，应用照常启动；游戏的大模型配置默认沿用主 Agent 的，需要时再单独填。
- [x] **4. 整条链路的文字模式**（中）
  - 问题：`chat` 直接和游戏对话，跳过了主 Agent。认游戏名和别名、游戏中闲聊、处理中插话、换游戏这些只能上真机测。
  - 做法：新命令 `agentcade-game play`：用文字代替语音识别和语音合成，经过主 Agent 和所有游戏，设备指令显示成文字。
- [x] **5. `chat --trace`**（小）
  - 问题：`chat` 只显示回复和设备指令，看不到大模型调用了哪些工具、结果是什么、拼好的系统提示词是什么样；远程游戏在真机测试时也看不到。
  - 做法：`chat` 和 4 的文字模式都加 `--trace`，打印每一步工具调用、参数、结果和系统提示词。
- [x] **6. 模板改用相对导入**（小）
  - 问题：内置游戏写 `from games.my_game.config`，远程游戏写 `from my_game.config`，游戏换一种方式发布就要改代码。
  - 做法：模板和内置游戏都改成 `from .config import Settings`，指南里去掉两种写法的说明。

## P1

- [ ] **7. 场景测试**（中）
  - 问题：`check` 只说一句“你好”，测的是协议，测不到玩法；指南里的真机清单全靠人工。
  - 做法：支持场景文件：一串用户输入，每一步写上期望，比如摇头、回复里不能出现答案、新题和上一题不同。`check --scenario` 自动跑，适合放进 CI。
- [ ] **8. 防剧透**（中）
  - 问题：不提前说出答案全靠提示词和开发者自己注意，猜谜语就出过问题。
  - 做法：提供 `self.hide(答案)` 和 `self.reveal()`：答案揭晓之前，框架检查每句要说的话，带出了答案就重新生成。单字答案（比如“水”）容易误判，要设计好匹配规则。
- [x] **9. 用户原话由框架传入**（小）
  - 问题：`original_text_input` 要大模型把原话一字不差地抄一遍，抄错一个字就校验失败，还多花 token。
  - 做法：随 12 一起做，工具不再有原话参数，直接读 `turn.text`。
- [ ] **10. 处理中的输入排队**（中）
  - 问题：游戏处理一条输入时，用户说的和游戏有关的话会被回一句“还在准备呢”就丢了，用户要再说一遍。
  - 做法：记下最后一句，处理完自动交给游戏；或者让游戏声明自己可以被打断。
- [ ] **11. 最小两个文件**（中）
  - 问题：一个游戏要 5 个文件，其中 `config.py`、`__init__.py` 每个游戏几乎一样，大模型的配置项每个 `settings.yaml` 都要重复一遍。
  - 做法：最小的游戏只要 `SKILL.md` 和 `agent.py`；大模型配置由框架内置，`settings.yaml` 和 `config.py` 只在有额外配置时才写。和 3 一起做。
- [x] **12. 用装饰器声明工具**（中）
  - 问题：每个工具要写闭包、`Tool(...)` 和参数类三处。
  - 做法：`@tool("出一道新题")` 把 `GameAgent` 的方法声明成工具，工具名默认是方法名，可以用 `name=` 改；参数从类型注解生成，`turn` 自动传入。
- [x] **13. 核对 SKILL.md 和工具**（小）
  - 问题：`SKILL.md` 用字符串写工具名，改了名字不会报错。
  - 做法：`check` 核对 `SKILL.md` 里写的“调用 工具名”都存在，不存在时报错并提示相近的名字；没被提到的工具给出提醒。
- [ ] **25. 必须说的内容被说两遍**（小，2026-10-23 新增）
  - 问题：1 的必须说的内容要原样出现在回复里。大模型稍微改写了一点（比如海龟汤的汤底换了几个字），框架就当成没说，再补一遍原文，用户会听到两次。`check` 里出现过好几次。
  - 做法：比较时忽略标点和空白，再按相似度判断是否已经说过。

## P2

- [ ] **14. 游戏主动说话**（大）
  - 问题：游戏只能在处理用户输入时说话，做不了倒计时、“时间到”这类提醒。
  - 做法：允许游戏在一局进行中主动推送回复，主 Agent 在机器人空闲时播报。要改协议。
- [ ] **15. 接管全部对话**（中）
  - 问题：哪些话转给游戏由主 Agent 判断，像角色扮演这种想接管全部对话的游戏做不到。
  - 做法：游戏在 `SKILL.md` 里声明“进行中所有的话都转给我”，只有“结束游戏”由主 Agent 处理。
- [ ] **16. 可选能力**（中）
  - 问题：能力只能全要；没有声明的指令被静默跳过，游戏不知道。
  - 做法：增加 `optional_capabilities`，并告诉游戏这一局实际有哪些能力，让它退而求其次，比如不能画图就口述。
- [ ] **17. 画图辅助和更多表情**（中，表情部分已完成）
  - 问题：画图要自己编码笔画，超出 12 笔、192 个点的限制就直接报错；表情只有开心和抱歉。
  - 已完成：游戏可以直接调用 SDK 的动画和官方表情。
  - 还要做：提供从 SVG 生成图案、自动简化到限制以内的函数；屏幕文字。
- [ ] **18. 远程游戏的存档**（中）
  - 问题：远程游戏每局都是新实例，拿不到玩家身份，做不到“玩过的题不再出”。
  - 做法：结束时游戏交回一小段存档，存在用户电脑上，下次开局带回来。数据留在用户这边，不需要玩家身份。
- [ ] **19. 单元测试辅助**（小）
  - 问题：每次测试都要调用大模型，没有单元测试的写法。
  - 做法：提供假的 `turn` 和 `self.robot`，直接调用工具，检查返回值和发出的 SDK 调用。
- [ ] **20. 说话和动作放在一处**（小）
  - 问题：说话用 `turn.say`，动作用 `self.robot`，分在两个对象上。
  - 做法：统一放到 `turn` 上。
- [ ] **21. 检查代理缓冲**（小）
  - 问题：反向代理把流式响应缓冲住了，要到真机上才会发现。
  - 做法：中间回复和最后一条同时到达时，`check` 给出提醒。

## P3

- [ ] **22. 按能力审核，不按版本**（小）
  - 问题：版本号是游戏自己报的。升了 `version` 用户会看到“未经审核”，不升也没人知道，结果是老实升版本的开发者吃亏。
  - 做法：只有要的能力变了才重新审核，版本号只用来显示；内容问题靠用户反馈和下架处理。在有第二个开发者提交游戏之前定下来。
- [ ] **23. 协议兼容策略**（小）
  - 问题：协议版本写死为 `desktop-game/7`，没说协议升级后旧游戏怎么办；从 6 升到 7 时没有兼容旧版。
  - 做法：写明兼容策略，比如新版本发布后，主 Agent 同时支持新旧两个版本至少三个月。
- [ ] **24. 依赖只写一处**（小）
  - 问题：内置游戏的依赖要在 `pyproject.toml` 和 `app.json` 里各写一遍。
  - 做法：从 `pyproject.toml` 生成 `app.json` 的依赖，或者由 CI 检查两边一致。
